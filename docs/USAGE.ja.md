# 使い方ガイド

**言語：** [English](USAGE.md) · 日本語 · [简体中文](USAGE.zh-Hans.md) · [Español](USAGE.es.md) · [हिन्दी](USAGE.hi.md) · [العربية](USAGE.ar.md) · [한국어](USAGE.ko.md) · [Русский](USAGE.ru.md) · [Français](USAGE.fr.md)

このアプリは、Quantus Network（QTC メインネット）の**通常フルノード**（ブロック生成はしない）を Android スマホで動かすものです。チェーンを同期し、すべてのブロックを自分で検証し、ピアへデータを中継します。**マイニングはしません。ウォレットもありません**（フレーズや報酬キーを扱うことは一切ありません）。

> 現在の状態: v3.0.2 を公開済み（2026-11-14、最新版。一部の端末でノードの同期が止まってしまう問題の修正版。v3.0.1 は 2026-11-12 の監査修正のみのメンテナンス版）。署名付き APK は [GitHub Releases](https://github.com/ogaworld369/quantus-android-node/releases) で SHA-256 チェックサム付きで配布しています。それ以前のテスト版は開発者から直接お渡ししていました。

## 動作要件

- Android 12 以降・arm64 の端末
- 空き容量: ノードのデータベースはプルーニング済み（保持は最新256ブロック分のみ）で、小さく収まります。実測（Pixel 9a、同期完了時点、2026-11-05）では合計 1.30GB（アプリ 96MB＋ノードデータ 1.20GB）でした。目安として 3GB 程度の空きを確保してください
- インターネット接続。初回同期は Wi-Fi を強く推奨します（下記）

動作確認済み: **Pixel 9a（GrapheneOS）**。その他の端末は動作見込みですが未確認です。別の機種で試した方は、動いた・動かなかったを含め GitHub の Issue で報告いただけると助かります。確認済みリストはその報告で増やしていきます。

## インストール

1. APK ファイルを [GitHub Releases](https://github.com/ogaworld369/quantus-android-node/releases) から用意します（インストール前に、リリースに併記された SHA-256 チェックサムでファイルが正しいか確認してください）。
2. ファイルアプリで APK を開き、Android に聞かれたらそのアプリからのインストールを許可します。
3. インストールして、**Quantus Node** を開きます。

## 初回起動と初回同期

1. （任意）先に**表示名**と**テレメトリ**設定を済ませておくと楽です（「設定」参照）。設定の反映にはノードの再起動（停止 → 開始）が必要です。
2. **「ノードを開始」**を押します。
3. 状態が**「同期中」**になり、ベストブロックが最高ブロックへ向けて増えていきます。Pixel 9a では初回同期（ジェネシスから）は毎秒約50ブロックのペースで、**2時間前後**が目安です。同期が完了すると約12秒に1ブロックの通常運転になり、状態表示が同期完了に変わります。
4. 初回同期中は、できれば**充電しながら Wi-Fi** で。モバイル回線でも同期できますが、通信量が多く、電池の減りも目立ちます（モバイル回線での同期中、30分で約11%の消費を実測）。同期完了後の定常負荷は小さいです。

アプリを開いたままにする必要はありません。ノードはフォアグラウンドサービスとして、画面を消しても、他のアプリを使っていても動き続けます（稼働中は通知が1つ常駐表示されます）。停止して再開しても、ダウンロード済みのチェーンは端末に残り、同期は続きから再開します。

## 画面の見方

画面の下部に3つのタブ（ホーム／つながり／会員カード）があります。ノード詳細と設定へはホームから移動します。

- **ホーム** — 脈動、ノードの状態（停止／起動中／同期中／同期完了／失敗）、主ボタンが中心です。稼働中は接続ピア数と今回の稼働時間、現在の QTC 価格も出ます。波紋は、同期完了中に新しいベストブロックを初めて観測したときだけ静かに1回出ます。起動に失敗した場合は通常の停止ではなく「失敗」として再試行ボタンが出ます。変更した設定がまだ反映されていない場合は、その確認へのリンクが出ます
- **つながり** — 自分のノードのネットワークの様子を描く画面です。接続しているピアと、自分が記録したチェックポイントの残像が広がります。競うための数字ではなく、つながりの様子を見るための画面で、ランキングはありません
- **ノード詳細** — ベストブロック／最高ブロック（自分のノードの位置と、ネットワークの先端）、同期差、ピア数、稼働時間と、**診断**のセクション（終了コード、サービスのメモ、起動試行ごとの記録、**ログを共有**）があります。停止中は前回セッションの値ではなく、累計の航跡を表示します
- **会員カード** — 会員番号（デバイスID）と、端末内の記録の代表的な数字（稼働時間の累計、観測した新ブロック数、観測したピア数の最大値）を載せた会員カードです。記録はこの端末にだけ保存され、外部に送信されることはなく、金銭価値もありません。自分の貢献の足跡で、見せるかどうかは自分で決められます
- **設定** — 下記の設定。最下部にアプリの版数が表示されます

## 設定

- **テレメトリに表示する**（既定オフ）— オンにすると、ノード名と稼働状態が公式テレメトリ（telemetry.quantus.com）で誰でも見える状態になります。一覧に載せたい場合だけオンにしてください。反映は次回のノード開始時（停止 → 開始）です
- **表示名** — ノードの名前（テレメトリ有効時は一覧にも出ます）。ダイアログで編集します。空欄なら既定名 `quantus-android-node` です。反映は次回のノード開始時です
- **言語** — 端末の設定に従うか、9言語（日本語・英語・簡体中文・スペイン語・ヒンディー語・アラビア語・韓国語・ロシア語・フランス語）から選べます。選ぶと即反映されます
- **稼働を記録する（DePIN）**（既定オフ）— オンにすると、ノードの稼働と中継の記録に署名して、この端末に残します（10分ごとのチェックポイント）。記録が自動でどこかへ送られることはありません。設定から証明バンドルとしてファイルに書き出し、自分で共有できます。オフにすると記録は止まりますが、それまでの記録は端末に残ります
- **設定をロック** — 上の設定（テレメトリ・表示名・言語・稼働の記録）をロックして、ノードを動かしたまま置いてある端末でうっかり変更してしまわないようにします。誤操作防止のためのもので、PIN はありません。ノードの開始・停止はロックされません。設定を変えるときは **設定をロック** をオフにしてください。

設定は自動でノードを再起動しません。稼働中にテレメトリや表示名を変えた場合は、変えた項目に未適用の印がつき、ホームにも未適用設定の確認リンクが出ます。反映は次回のノード開始時（停止 → 開始）です。

**ログを共有** は **ノード詳細 → 診断** の中にあります。ノードのログをテキストで共有するもので、不具合報告のときにこれを添付してください。公開の場に貼る前に内容を確認してください。ログには自ノードのグローバル IP アドレスやピア情報が含まれうる場合があります。共有ダイアログでは、表示名・この端末自身のネットワークアドレス・アプリ内パスのマスキングが使えます（既定オン）。ただし、ピア経由で知った外向きのアドレスはマスキングの対象外です。

## 日常の使い方

- ノードが止まるのは、**「ノードを停止」**を押したとき、アプリを強制終了したとき、スマホを再起動したときだけです
- スマホを再起動した後は、アプリを開いて**「ノードを開始」**を押し直してください（起動時の自動開始は未実装です）
- メーカー独自の省電力（Samsung、Xiaomi など）が強い端末では、バックグラウンドのサービスが止められることがあります。ノードが勝手に止まる場合は、システム設定でこのアプリを電池最適化の対象外にしてください
- 余ったスマホを24時間コンセントに挿して使う場合は、時々バッテリーの状態を見てください。古いリチウム電池は膨張することがあります。風通しの良い場所に置き、端末に充電上限の設定があれば使うのがおすすめです

## 困ったとき

- **ノードがすぐ終了する** — **ノード詳細 → 診断 → ログを共有** でログを取り、GitHub の Issue（不具合テンプレート）に添付してください。ログには起動の試行ごとに終了理由が残っています
- **ピア数が0のまま** — 接続を確認して、停止 → 開始を1回試してください
- **同期が止まる（ネットワークは進むのに自分のベストブロックが動かない）** — この形を検出すると、アプリが自動でノードを再起動します（24時間に最大3回まで）。繰り返す場合は安定した Wi-Fi に切り替え、停止 → 開始を1回試してください
- **テレメトリに自分のノードが出ない** — テレメトリ設定がオンか、オンにした後にノードを再起動したかを確認してください（掲載は確認済みです。開発者自身のノードが公式一覧に表示されています）
- **容量について** — データベースは設計上、最新256ブロック分にプルーニングされます。アプリをアンインストールするとデータベースとノードの身元キーは削除され、再インストールすると新しい身元で同期し直しになります

質問・端末の動作報告・提案は GitHub の Issue へどうぞ。セキュリティの問題は公開 Issue ではなく [SECURITY.md](../SECURITY.md) の手順でお願いします。
