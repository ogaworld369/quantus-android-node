# 사용 가이드

**언어:** [English](USAGE.md) · [日本語](USAGE.ja.md) · [简体中文](USAGE.zh-Hans.md) · [Español](USAGE.es.md) · [हिन्दी](USAGE.hi.md) · [العربية](USAGE.ar.md) · 한국어 · [Русский](USAGE.ru.md) · [Français](USAGE.fr.md)

이 앱은 Android 스마트폰에서 Quantus Network(QTC 메인넷)의 **비검증자 풀 노드**를 실행합니다. 체인을 동기화하고, 모든 블록을 스스로 검증하며, 피어에게 데이터를 중계합니다. **마이닝은 하지 않고, 지갑도 없습니다** — 시드 구절이나 보상 키를 다루는 일은 전혀 없습니다.

> 상태: v0.1.0 공개됨(2026-11-04). 서명된 APK는 SHA-256 체크섬과 함께 [GitHub Releases](https://github.com/ogaworld369/quantus-android-node/releases)에 게시되어 있습니다. 이전 테스트 빌드는 유지관리자가 직접 공유했습니다.

## 동작 요구 사항

- Android 12 이상, arm64 기기
- 여유 공간: 노드 데이터베이스는 프루닝되어(최신 256개 블록만 유지) 작게 유지됩니다. 실측(Pixel 9a, 전체 동기화 완료 시점, 2026-11-05): 총 1.30GB(앱 96MB + 노드 데이터 1.20GB). 여유 공간은 최소 약 3GB 정도 확보해 두세요
- 인터넷 연결. 첫 동기화에는 Wi-Fi를 강력히 권장합니다(아래 참조)

지금까지 확인된 기기: **GrapheneOS를 실행하는 Pixel 9a**. 다른 기기도 동작할 것으로 예상되지만 확인되지는 않았습니다. 다른 기종에서 시도해 보셨다면, 동작 여부와 함께 GitHub Issue로 알려 주세요. 확인된 기기 목록은 그 보고로 늘어납니다.

## 설치

1. APK 파일을 준비합니다(당분간은 유지관리자로부터, 공개 릴리스 시작 후에는 GitHub Releases에서. 설치 전에 릴리스와 함께 게시된 SHA-256 체크섬을 확인하세요).
2. 파일 앱으로 APK를 열고, Android가 물으면 해당 출처에서의 설치를 허용합니다.
3. 설치한 뒤 **Quantus Node**를 엽니다.

## 첫 실행과 초기 동기화

1. (선택) 먼저 **표시 이름**과 **텔레메트리** 옵션을 설정해 두면 편합니다(설정 참조). 설정 변경은 노드 재시작(정지 → 시작) 후 적용됩니다.
2. **노드 시작**을 누릅니다.
3. 상태가 **동기화 중**으로 표시되고 베스트 블록이 최고 블록을 향해 올라갑니다. Pixel 9a에서는 제네시스부터의 첫 동기화가 초당 약 50블록 속도로 진행되어 **약 2시간**이 걸립니다. 동기화가 끝나면 약 12초마다 새 블록이 도착하고 상태가 동기화 완료로 바뀝니다.
4. 첫 동기화 중에는 가능하면 **충전하면서 Wi-Fi**에 연결해 두세요. 모바일 데이터로도 동기화는 되지만, 데이터 다운로드량이 많고 배터리 소모도 눈에 띄게 큽니다(모바일 데이터 동기화 중 30분에 약 11% 소모를 실측). 동기화 완료 후의 상시 부하는 작습니다.

앱을 열어 둘 필요는 없습니다. 노드는 포그라운드 서비스로 실행되어, 화면을 꺼도 다른 앱을 사용해도 계속 동작하며, 실행 중에는 상시 알림이 표시됩니다. 정지 후 다시 시작해도 다운로드한 체인은 기기에 남아 있어 동기화는 이어서 재개됩니다.

## 화면 설명

- **상태** — 동기화 중/동기화 완료. 새 베스트 블록이 도착할 때마다 펄스 뷰에 조용한 파문이 한 번 표시됩니다
- **베스트 블록 / 최고 블록** — 내 노드의 위치와 알려진 네트워크 선단의 비교
- **피어 수** — 연결된 노드의 수
- **항적** — 이 기기에만 저장되는 기록: 누적 가동 시간, 관측한 새 블록 수, 관측한 피어 수의 최대값. 외부로 전송되지 않고 금전적 가치도 없습니다. 그저 자신의 기여의 발자취입니다
- **양자 워치** — 내 노드의 동기화 상태와 네트워크 연결 건전성(외부 위협 정보는 아직 미구현입니다)

## 설정

- **텔레메트리에 표시** (기본 꺼짐) — 켜면 노드 이름과 실시간 상태가 공식 텔레메트리(telemetry.quantus.com)에 누구나 볼 수 있게 공개됩니다. 목록에 올리고 싶을 때만 켜세요. 다음 노드 시작(정지 → 시작)부터 적용됩니다.
- **표시 이름** — 노드가 사용하는 이름(텔레메트리가 켜져 있으면 목록에도 표시됩니다). 비워 두면 기본 이름 `quantus-android-node`가 됩니다. 다음 노드 시작부터 적용됩니다.
- **언어** — 기기 설정을 따르거나, 9개 언어(일본어, 영어, 간체 중국어, 스페인어, 힌디어, 아랍어, 한국어, 러시아어, 프랑스어) 중 선택할 수 있습니다.
- **로그 공유** — 노드 로그를 텍스트로 공유합니다. 문제를 보고할 때 이것을 첨부해 주세요. 공개된 장소에 로그를 붙여 넣기 전에 내용을 먼저 확인해 주세요. 로그에는 내 노드의 공인 IP 주소와 피어 정보가 포함될 수 있습니다.
- **설정 잠금** — 위의 세 가지 설정(텔레메트리, 표시 이름, 언어)을 잠가, 노드를 실행한 채로 둔 휴대전화에서 실수로 변경되지 않게 합니다. 오조작 방지를 위한 기능일 뿐 PIN은 없으며, 노드의 시작과 정지는 잠기지 않습니다. 설정을 다시 변경하려면 **설정 잠금**을 끄세요.

설정은 스스로 노드를 재시작하지 않습니다. 노드가 실행 중일 때 변경하면, 화면에 재시작(정지 → 시작)이 필요하다고 표시됩니다.

## 일상적인 운용

- 노드가 멈추는 경우는 **노드 정지**를 눌렀을 때, 앱을 강제 종료했을 때, 스마트폰을 재부팅했을 때뿐입니다.
- 스마트폰 재부팅 후에는 앱을 열고 **노드 시작**을 다시 눌러 주세요(부팅 시 자동 시작은 아직 미구현입니다).
- 일부 제조사의 Android(Samsung, Xiaomi 등)는 배터리 절전이 강해서 백그라운드 서비스를 멈출 수 있습니다. 노드가 저절로 멈춘다면, 시스템 설정에서 이 앱을 배터리 최적화 대상에서 제외해 주세요.
- 여분의 스마트폰을 24시간 충전기에 꽂아 두고 쓰시나요? 가끔 배터리 상태를 확인하세요. 오래된 리튬 배터리는 부풀 수 있습니다. 통풍이 잘 되는 곳에 두고, 기기가 충전 상한 설정을 제공하면 사용하는 것을 권장합니다.

## 문제가 생겼을 때

- **노드가 바로 종료됨** — 설정의 **로그 공유**로 로그를 가져와 GitHub Issue(버그 리포트 템플릿)에 첨부해 주세요. 로그에는 시작 시도마다 종료 이유가 남아 있습니다.
- **피어 수가 0에서 안 늘어남** — 연결을 확인한 뒤 정지 → 시작을 한 번 해 보세요.
- **텔레메트리에 내 노드가 안 보임** — 텔레메트리 옵션이 켜져 있는지, 켠 뒤에 노드를 재시작했는지 확인하세요(목록 표시 동작은 현재도 검증 중입니다).
- **용량 관련** — 데이터베이스는 설계상 최신 256개 블록으로 프루닝됩니다. 앱을 삭제하면 데이터베이스와 노드의 신원 키가 지워지고, 재설치하면 새 신원으로 다시 동기화합니다.

질문, 기기 동작 보고, 제안은 GitHub Issue로 환영합니다. 보안 문제는 공개 Issue가 아니라 [SECURITY.md](../SECURITY.md)의 절차를 따라 주세요.
